# Подключение котировок

## Portals: публичный источник

В режиме `MARKET_PROVIDER=portals` приложение обращается к HTTPS API официального [Portals](https://portal-market.com). Проверено 10 октября 2026 без заголовка авторизации:

- `GET /api/collections?limit=100&offset=N` — пагинация по 100; проверено 122 коллекции. `floor_price`, `day_volume`, `sales_24h_count`, `listed_count`, `photo_url` нормализуются в TON. Средняя продажа = объём / число продаж, без собственной верификации сделок.
- `GET /api/nfts/search?offset=0&limit=20&sort_by=price%20asc&status=listed&collection_ids=UUID` — 20 дешёвых предложений выбранной коллекции. Сервер ещё раз проверяет collection_id, status, цену и ID. Атрибуты — model, backdrop, symbol. Публичная ссылка ведёт к карточке подарка в Portals.

API публично доступен, но стабильный документированный контракт и гарантии полноты/задержки отсутствуют. Опрос коллекций раз в 120 секунд, отсутствие параллельных циклов, backoff с Retry-After; предложения имеют общий кэш на минуту и объединяют одновременные запросы. Доступен максимум 1000 коллекций; повторённая страница отвергается, а не считается новым рынком. При ошибках сохраняется последний реальный снимок, демо не подставляется.

`updatedAt` для Portals — **время нашего наблюдения**, а не обещание актуальности исходной котировки. `created_at` коллекции для этого не подходит. Статус помечается `timestampKind=observed`; в UI написано «получено». После 300 секунд без обновления score и ценовые алерты приостанавливаются. Изменение за 24ч вычисляется из собственной истории спустя сутки; неопределённая метрика источника `floor_changes` не используется без подтверждённого окна.

Некоторые коллекции не имеют `photo_url` и получают нейтральный значок. Для остальных разрешены только известные HTTPS CDN Portals и Fragment; произвольные изображения/протоколы отвергаются. Фото конкретного листинга — из ответа источника.

Флор коллекции не оценивает отдельную модель или фон. Процент у предложения означает наценку к наблюдаемому флору коллекции, а не скидку к справедливой стоимости. Устаревший флор не участвует в таком сравнении. `total_count=0` при непустом results не показывается как ноль доступных NFT. Покупки выполняются самим пользователем на маркете; приложение не подключает кошелёк.

## MRKT и Gift Charts

В Mini App и закреплённом приветствии есть ссылки [MRKT](https://t.me/main_mrkt_bot), [Gift Charts](https://t.me/gift_charts_bot), [Portals](https://t.me/portals). Статусы показывают подключён ли именно источник данных.

Публичный сайт Gift Charts доступен, но его `/api/v1/gifts` вернул 401 Missing authorization. Проверка остановлена без обхода авторизации. Официальный сайт MRKT просмотрен; доступный и подтверждённый API котировок без авторизации не найден. Это не утверждение, что такого API не существует. Для интеграции нужны доступ от поставщика или нормализованный feed. Токен нашего бота не является ключом этих маркетов; Telegram session string пользователя не извлекается.


## GiftAsset

Адаптер реализован по [документации владельца API](https://github.com/GIFT-ASSET/gift_asset_api/blob/main/DOCS.md), прочитанной 10 октября 2026 года. Живой доступ не проверен: ключа нет. Не используются неофициальные Telegram session strings или догадки об авторизации Portals/MRKT.

На каждом опросе выполняются два HTTPS GET:

- `/api/v1/gifts/get_gifts_price_list`: `collection_floors[collection]` содержит `portals`, `mrkt`, `tonnel`, `getgems`, `last_update`.
- `/api/v1/gifts/get_custom_collections_volumes?maxtime=86400`: по провайдерам `collections[]` с `collection_name`, `sales_count`, `sales_sum`.

Заголовок задаётся через `PROVIDER_AUTH_HEADER` и `PROVIDER_AUTH_VALUE` после подтверждения у провайдера. Redirect запрещён, чтобы ключ не ушёл на другой хост. TLS проверяется; таймаут 12 секунд, максимум 4 MiB. Неуспешный запрос котировок не заменяет кэш. Если недоступны только продажи, флоры обновляются, метрики продаж — `null`. Пропущенные коллекции в статистике продаж тоже `null`, а не выдуманный ноль. Продажи и объём суммируются по известным маркетам. Средняя цена = объём / число продаж; доступность данных всех маркетов не гарантирована.

Нужно подтвердить у поставщика, что цены выражены в TON, полная выдача не требует пагинации и временная метка означает момент получения сопоставимых котировок. Переносимая схема этого MVP принимает до 1000 коллекций. Поллер на фиксированном интервале с увеличением пауз после ошибок и учётом Retry-After, без обхода блокировок и без наложенных циклов. На старте `change24h=null`; после накопления снимка 24ч назад (с допуском не более `STALE_AFTER_SECONDS`) вычисляется изменение минимального флора.

## Собственный feed

В `.env`: `MARKET_PROVIDER=feed`, `MARKET_FEED_URL=https://your-source.example/gifts.json`. При необходимости используется тот же настроенный заголовок авторизации. URL — только серверная конфигурация, пользователь не может его подменить через приложение.

```json
{
  "gifts": [
    {
      "id": "toy-bear",
      "name": "Toy Bear",
      "updatedAt": "2026-10-10T12:00:00Z",
      "markets": [
        { "name": "Portals", "floor": 31.4, "listings": 40 },
        { "name": "MRKT", "floor": 32.0, "listings": 35 }
      ],
      "sales24h": 186,
      "volume24h": 5934,
      "avgSale24h": 31.9,
      "change24h": 4.7
    }
  ]
}
```

Пример — схема, не текущая котировка. `updatedAt`: ISO 8601 с timezone или число миллисекунд Unix. Это метка источника, а не время запроса. Сервер не освежает старую котировку временем получения. Обязательны уникальный `id` (a-z, 0-9, дефис; 1–80 символов), название, корректная метка и минимум один маркет с положительным флором в TON. Неизвестные `sales24h`, `volume24h`, `avgSale24h`, `change24h`, `listings` пропускаются или равны null. Метрики продаж должны относиться к одному окну 24ч, а объём — к тому же набору сделок. Дубли маркетов/ID и некорректные даты/цены отклоняют снимок целиком.

В режиме feed используются локальные нейтральные иллюстрации, не подлинные NFT-превью. Portals отдельно загружает изображения из своих ответов. Media из внешнего feed пока не загружается. История и редкие атрибуты не импортируются; график строится из подтверждённых серверных наблюдений. Новые unknown коллекции получают значок подарка.
