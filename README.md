# Gift Signal

Мини-апка Telegram для наблюдения за NFT-подарками: рынок, объяснимые сигналы, ручной портфель, избранное, ценовые уведомления и ассистент. Это работающий MVP с сохраняемой базой, а не опубликованный сервис. В локальном Telegram-запуске подключены реальные котировки Portals. Для отдельного браузерного просмотра можно включить **локальное демо**. Котировки, графики, атрибуты и иллюстрации в демо вымышлены.

## Посмотреть сейчас

Нужен **Node.js 24 LTS** (минимум 22.16). На этом компьютере проверено с Node 24.13.0. Используется встроенный `node:sqlite`, который в этой версии выводит предупреждение об экспериментальном статусе. Внешних npm-зависимостей нет; `npm install` не нужен.

```sh
cd "/Users/sux6s/Documents/ChatGPT/NFT BOT"
npm start
```

Для браузерного демо запусти `APP_MODE=demo PORT=3000 DB_PATH=./data/gifts.sqlite npm start`, затем открой http://127.0.0.1:3000. Обычный `npm start` использует настройки `.env`. Остановить сервер — Ctrl+C. Демо слушает только этот компьютер: его нельзя публиковать через туннель. Покупки, изменения и избранное сохраняются в `data/gifts.sqlite`. Файлы базы и `.env` исключены из Git.

## Запустить внутри Telegram с этого компьютера

Для @tradingnftgift_bot подготовлен временный запуск без аренды сервера. Запиши токен в локальный `.env` и выполни:

```sh
cd "/Users/sux6s/Documents/ChatGPT/NFT BOT"
npm run telegram:local
```

Нужен `cloudflared`: в этом проекте он скачан в `.tools` из официального релиза Cloudflare. На другом Mac можно установить через `brew install cloudflared`. Команда проверяет бота, создаёт [временный HTTPS-туннель](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/), запускает сервер на 127.0.0.1:3001 и бот, который обновляет кнопку меню. Открой бота, отправь `/start`, нажми «Открыть Mini App». Старые сообщения могут содержать прежний адрес; после перезапуска отправь `/start` снова.

В `.env` теперь настроены `LOCAL_APP_MODE=live` и `MARKET_PROVIDER=portals`: вход проверяется по подписи Telegram, а флоры и предложения загружаются из публичного API Portals. Ключ маркетплейса для этого источника не понадобился. Опрос коллекций — раз в 120 секунд, предложения кэшируются на минуту. База `data/telegram-preview.sqlite` сохранена, несмотря на историческое имя файла; учёт покупок ручной.

Для проверки с вымышленными ценами укажи `LOCAL_APP_MODE=preview`. Этот режим никогда не отправляет рыночные алерты. Реальный режим не подставляет демо при ошибке источника.

В пустом чате Telegram показывает описание бота до нажатия «Начать». После `/start` бот создаёт и закрепляет одно приветствие с кнопкой запуска. Повторный `/start` не засоряет чат копиями. При смене адреса туннеля сохранённая кнопка обновляется. Открытие уже существующего чата само по себе не создаёт Telegram-событие: для сообщения нужен `/start`.

Компьютер должен быть включён, подключён к интернету и с открытой крышкой. На macOS команда временно предотвращает автоматический сон, пока запущена. Ctrl+C останавливает сервер, бот и туннель. Туннель не имеет гарантии доступности; адрес меняется при новом запуске. Кнопка меню обновляется автоматически, а Main Mini App в BotFather, если настроена вручную, требует обновления URL. Платный сервер для такого временного запуска не нужен.

## Возможности

- Обзор: объём продаж по данным источника, список активных коллекций, график флора и рейтинг внимания.
- Рынок: поиск, сетка/таблица, пять сортировок, избранное.
- Детальная карточка: котировки по маркетам, история наблюдений, продажи/час, калькулятор спреда с затратами. Для Portals есть список 20 дешёвых предложений конкретной коллекции: цена, модель, фон, узор, фото, бюджет и ссылка на NFT. Цена модели пока не оценивается; флор коллекции служит ориентиром.
- Портфель: добавление, редактирование и удаление покупок, количество, цена за единицу, дата, оценка, P/L, ROI, CSV. Учёт покупок ручной, импорт Telegram-инвентаря пока не реализован.
- Уведомления: порог флора ≥ или ≤, только своему подтверждённому Telegram ID, одна доставка при выполнении условия, повтор при сетевой ошибке. Для разрешения доставки нужен `/start`; `/stop` отключает её. В демо сообщения не отправляются.
- Ассистент: локальные ответы по правилам; с отдельным ключом — OpenAI Responses API с текущим снимком данных. При ошибке AI включается явно обозначенный локальный ответ.
- Сервер: проверка HMAC `initData` и возраста авторизации, случайные серверные сессии, изоляция данных пользователей, проверка ввода, размер запросов, лимиты запросов, CSP, HTTPS-источник цен, кэш и история в SQLite.

## Что потребуется от владельца

1. **Бот в @BotFather и его username.** Получи токен командой `/newbot` и запиши в `.env` у себя/на сервере. Токен, ключи API и доступы не нужно публиковать в чате или GitHub.
2. **Для постоянной работы — сервер с постоянным диском и HTTPS-адресом.** Сейчас Mini App работает с компьютера владельца; аренда для этого не нужна. Подойдёт VPS с Docker и доменом, направленным на его IP. Данные SQLite должны переживать перезапуск контейнеров. Хостинг в этом проекте не куплен и не настроен.
3. **Для Portals — ничего дополнительно.** Публичные флоры и листинги проверены 10 октября 2026; API не документирует стабильность и может изменить правила доступа. Для сравнения с MRKT и Gift Charts нужен отдельный подтверждённый источник: официальный API-доступ или [нормализованный feed](docs/provider.md). Gift Charts при проверке вернул 401 без авторизации. В приложении эти два сервиса доступны по ссылкам, их цены не имитируются. Альтернативный агрегатор [GiftAsset](https://github.com/GIFT-ASSET/gift_asset_api/blob/main/DOCS.md) уже имеет адаптер, но требует согласованного ключа.
4. **Для свободного AI-диалога — отдельный OpenAI API-ключ и бюджет.** Это необязательно для рынка и портфеля. Подписка на ChatGPT не подставляет ключ автоматически. Внешней модели передаются вопрос, рыночный снимок и расчёты портфеля; Telegram ID/имя и секреты не передаются.

Для настройки далее достаточно сообщить **username бота, выбранный хостинг/домен и доступный источник данных**. Секреты вводи в `.env` лично. Seed-фразу, пароль Telegram и пользовательскую session string приложение не использует.

## Настройка реального режима

Скопируй `.env.example` в `.env`, затем заполни:

```dotenv
APP_MODE=live
HOST=127.0.0.1
BOT_TOKEN=вставь_локально
PUBLIC_URL=https://gifts.example.com
MARKET_PROVIDER=portals
PORTALS_BASE_URL=https://portal-market.com/api
POLL_INTERVAL_SECONDS=120
STALE_AFTER_SECONDS=300
```

Запускаются **два процесса**: `npm start` (сайт и сбор данных) и `npm run bot` (бот и отправка уведомлений). Они используют одну базу. Подключи обратный прокси с HTTPS; готовый вариант ниже. `PUBLIC_URL` должен совпадать с внешним адресом приложения. Live-вход в обычном браузере запрещён: открывай из Telegram.

В @BotFather: `/mybots` → свой бот → **Bot Settings → Configure Mini App** → URL приложения. Также можно настроить кнопку меню. Код бота устанавливает кнопку через `setChatMenuButton` и отдаёт кнопку запуска после `/start`. Названия меню Telegram могут отличаться в разных клиентах. Основа интеграции — [документация Telegram Mini Apps](https://core.telegram.org/bots/webapps).

На VPS с Docker Compose и доменом:

1. Заполни `.env` в корне, добавь `DOMAIN=gifts.example.com` и `PUBLIC_URL=https://gifts.example.com`.
2. Настрой DNS домена на IP VPS, открой входящие 80/443.
3. Запусти:

```sh
docker compose --env-file .env -f deploy/compose.yaml up -d --build
docker compose --env-file .env -f deploy/compose.yaml logs --tail=100
```

Caddy получает сертификат, наружу доступны только 80/443. SQLite находится в именованном томе `gift_data`. Команда `docker compose down -v` удалит данные: не используй её для обычного обновления. Один экземпляр app и один bot; бот останавливается при конфликте polling/webhook. Для этого бота существующий webhook нужно отключить перед polling, если он был настроен раньше.

## Как считаются цифры

`invested = quantity × buyPrice`. Оценка позиции = количество × минимальный флор коллекции; P/L = оценка − вложено; ROI = P/L / вложено × 100. Если для позиции нет котировки, полная оценка не показывается, P/L/ROI относятся только к оценённым позициям. Устаревшие оценки помечаются. Флор — цена предложения, не гарантированная выручка; комиссии, атрибуты и реализованные сделки не учтены.

Score = 45 × нормализованная логарифмическая ликвидность + 30 × положительный импульс + 15 × скидка флора к средней продаже + 10 × число маркетов. Нормализация: 500 продаж/24ч, +15% изменения, 20% скидки и 3 маркета соответственно. Неизвестные метрики дают 0; устаревшие данные отключают score. Это эвристика без бэктеста, **не процент вероятности прибыльной сделки**. Для live-адаптера изменение /24ч появится после накопления истории минимум за сутки; графики не дорисовываются.

Разница флоров не исполнимый арбитраж: максимум может относиться к другим атрибутам и не иметь покупателя. Калькулятор показывает сценарий: `highFloor × (1 − sellFee) − lowFloor × (1 + buyFee) − transferCost`. Тарифы по умолчанию не заданы — вводи свои реальные затраты.

## Проверка и эксплуатация

```sh
npm run check
npm test
```

Отчёт с проверенными сценариями и ограничениями: [docs/verification.md](docs/verification.md). HTTP-тестам нужны разрешённые localhost-порты. Тесты используют временные базы, не отправляют сообщения и не требуют внешних ключей.

`GET /health` проверяет доступность процесса, `/api/status` — состояние данных. При 403/429, таймауте или неверном JSON сохраняется последний реальный снимок; после порога свежести сигналы и алерты по нему не работают. Нет обхода Cloudflare, ротации аккаунтов или подмены данных демонстрацией. При 429 увеличь интервал в соответствии с тарифом; поллер соблюдает Retry-After (до 24ч) и увеличивает паузу при последовательных ошибках до часа.

Бэкап локальной базы, корректный для SQLite WAL:

```sh
node --env-file-if-exists=.env scripts/backup.js /private/path/gifts-backup.sqlite
```

Сохраняй копии вне сервера и регулярно проверяй восстановление. Скрипт также включён в Docker-образ: запускай его через `docker compose ... exec app node scripts/backup.js /app/data/backups/copy.sqlite`, затем копируй бэкап вне тома. Восстанавливай с остановленными app/bot, отдельно убери старые `-wal`/`-shm` только после корректной остановки. Автоматическая облачная доставка бэкапов и мониторинг пока не настроены.

## Практические границы MVP

Нет автопокупок, подключения кошелька, Stars-подписки, импорта Telegram-инвентаря, торговли и оценки редких атрибутов в live. Нет бэктеста сигналов, выявления wash trading и проверки доступности переводов. Локальная история хранится 30 дней; начальная история зависит от времени сбора. AI-ответы могут ошибаться, а цены источника могут запаздывать. Доставка уведомлений имеет семантику at-least-once: при аварии между отправкой и записью результата возможен повтор.

Архитектура рассчитана на небольшой пилот на одном сервере. Перед ростом нужны проверка нагрузки, алерты эксплуатации, резервирование и при необходимости PostgreSQL/очередь. Для поиска действительно выгодных покупок дальше нужны сопоставимые флоры моделей и фонов, история реальных продаж, комиссии и второй маркет. Рейтинг внимания и дешёвое предложение не равны подтверждённой прибыльной сделке.
